# report — 학교장 보고서 양식으로 보고서 쓰기

기준 양식: 소방학교장이 만든 「천안캠퍼스 역할 재정립 방안 검토(안) 보고」(2022. 12., 153쪽)의 짜임과 표기.
도구: `tools/report/make_report.py` (표준 라이브러리만) · 원고 견본: `.claude/skills/report/원고-견본.txt`

사용자가 다른 양식 · 목차 · 최종본을 주면 그 자료가 먼저다. 아래는 따로 지시가 없을 때의 기본값이다.

## 1. 문서 구성과 순서

| 순서 | 제목 | 넣을 내용 | 자주 쓰는 형식 |
|---|---|---|---|
| Ⅰ | 관련근거 | 법령 조문(시행일), 상위 계획 · 지시사항(문서번호 · 날짜) | ○ 한 줄씩, ※ 기준일 |
| Ⅱ | 배경 및 중요성 | 무엇이 문제이고 왜 지금인지. 근거 숫자 1~2개 | ○ + ↳ 결과, 문제점 상자 |
| Ⅲ | 추진목표 | 한 문장 목표(언제까지 · 무엇을 · 어느 수준) + 추진과제 3~5개 | 형광 강조, 체계도 그림 자리 |
| Ⅳ | 주요현황 | 인력 · 시설 · 장비 · 실적. 확보한 여건과 모자란 여건을 나눠 적음 | 표(전 대비 ▲▼), 사진 자리 |
| Ⅴ | 추진경과 | 날짜순 사실: 계획 · 회의 · 현지 확인 · 승인(문서번호, 참석 인원, 결과) | ○ 날짜 + 내용 + {{결과}} |
| Ⅵ | 추진계획 | 추진 방향 → 세부 내용 → 일정 → 예산 → 안전관리 → 협조사항 | □ 소제목, 일정 · 예산 표 |
| Ⅶ | 기대효과 | 현장 · 조직 · 예산 관점에서 달라지는 점 | ○ (관점) 내용 |
| Ⅷ | 향후계획 | 단계별 일정, 결정 · 협조가 필요한 사항 | ○ (1단계) 시기: 할 일 |
| — | 붙임 | 긴 표, 회의 결과, 산출 내역, 현장 사진 | `@붙임 1 제목` |

- 여덟 제목은 순서와 이름을 그대로 쓴다. 자료가 없는 절도 지우지 않고 `○ 확인 필요` 로 남긴다(사용자가 빼라고 하면 뺀다).
- 짧은 보고(A4 1~2쪽)는 표지 없이 첫 쪽 머리(부서 상자 + 제목 상자)에서 바로 시작한다. 10쪽이 넘으면 `@표지` 를 넣고, 목차는 한글에서 쪽 번호를 붙여 넣도록 사용자에게 알린다.
- 본문이 2쪽을 넘기면 긴 표 · 세부 내역은 붙임으로 돌린다.

## 2. 제목 형식

- 메인제목: 무엇에 대한 어떤 문서인지 — `○○○ 추진계획(안) 보고`, `○○ 방안 검토(안) 보고`, `○○ 결과 보고`.
- 부제목: 이 보고가 노리는 효과 · 방향을 한 줄 구호로. 제목 위에 `- 부제목 -` 으로 들어간다. 예: `- 소방 교육훈련 再도약의 디딤돌 -`.
- 왼쪽 위 상자: 첫 줄 부서(`지휘역량강화센터 지휘역량팀`), 둘째 줄 날짜(`2026. 11. 22.(일)`). 요일은 달력으로 확인한다.
- 판 번호(v2 …)는 파일 이름에만 붙이고 제목에는 넣지 않는다.

## 3. 문체와 표기

- 개조식. 문장은 `~함`, `~임` 으로 끝낸다(`~예정임`, `~필요함`, `~하고자 함`, `~추진 중임`). `~습니다 · ~한다` 금지. 명사로 끝나는 줄(`○ 2026. 3. 5. 착수회의 개최`)은 추진경과 · 일정에서만 쓴다.
- 한 줄에 한 가지. 두 줄을 넘기면 `-` 나 `↳` 로 나눈다.
- 기호 단계: `Ⅰ.` 큰 제목 → `□` 소제목 → `○` 본문 → `-` 세부 → `↳` 결과 · 이어지는 조치 → `※` 참고 → `*` 각주.
- `○ (괄호 소제목) 내용` 꼴을 즐겨 쓴다: `○ (기간) …`, `○ (인원) …`, `○ (점검방법) …`.
- 강조는 아껴 쓴다: 핵심어 **굵게**, 결론 __밑줄__, 그 절에서 하나뿐인 핵심 ==형광==, 결과 · 판정 {{파랑}}.
- 날짜 `2026. 11. 22.`, 줄일 때 `'26. 11.` · `'27년`. 금액은 단위(천원 · 백만원)를 표 오른쪽 위에 적는다.

### 숫자

- **숫자가 둘 이상 나오면 표로 만든다.** 문장 안에는 가장 중요한 숫자 하나만 남긴다.
- 표 제목은 표 위에(`〈 제목 〉`), 단위는 오른쪽 위에, 기준일 · 출처는 표 아래 `※` 로.
- **전과 비교할 수 있으면 증감 칸을 둔다.** 증가 `▲ 12`, 감소 `▼ 3`, 같으면 `-`. 비율은 `▲ 12.5%`, 비율끼리의 차는 `%p`. `△ ▽ + −` 는 쓰지 않는다. (도구가 ▲ 는 빨강, ▼ 는 파랑으로 칠한다.)
- 증감은 직접 계산하고 검산한다. 본문 · 표 · 붙임의 같은 숫자(연도 · 인원 · 금액 · 수량)가 서로 맞는지 마지막에 대조한다.
- **자료에 없는 숫자 · 날짜 · 문서번호 · 담당자 · 결정사항은 만들지 않고 `확인 필요` 로 비워 둔다.** 추정값도 넣지 않는다. 증감을 계산할 수 없으면 증감 칸도 `확인 필요`. (도구가 노란 바탕 빨간 글씨로 표시한다.)
- 원문끼리 숫자가 다르면 한쪽을 고르지 말고 `확인 필요` 로 두고, 어디와 어디가 다른지 사용자에게 알린다.
- 법령 · 지정요건 · 예산 기준은 최신 공식 원문을 확인하고 시행일 · 기준일을 적는다. 확인하지 못했으면 `확인 필요`.

### 도표 · 그림 자리

글만 이어지는 쪽이 없게, 아래 자리를 먼저 잡아 둔다(자리에는 무엇을 넣을지 한 줄로 적는다). 한 쪽에 하나 정도가 알맞다.

| 넣는 곳 | 알맞은 것 |
|---|---|
| 추진목표 | 목표 체계도(비전 → 목표 → 추진과제) |
| 주요현황 | 현황 사진, 위치도 · 배치도, 연도별 추이 그래프 |
| 추진경과 | 회의 · 현장 확인 사진(사진 아래 `내용(날짜)`) |
| 추진계획 | 조직도, 절차 흐름도(□ ⇨ □ ⇨ □), 일정표(간트), 현재(As-Is) → 앞으로(To-Be) 비교 |
| 붙임 | 조치 전 · 후 사진 표, 도면 |

- 사용자가 사진 · 그림을 주지 않았으면 자리만 둔다. 실제 사진처럼 보이는 그림을 지어내지 않는다.
- 정확해야 하는 도면 · 지도 · 통계 그래프는 생성 그림으로 그리지 않는다(자료를 받아 넣는다).

## 4. 원고 쓰기 → hwpx 만들기

1. 사용자가 준 자료를 다 읽고, 원고(`.txt`)를 scratchpad 에 쓴다. `.claude/skills/report/원고-견본.txt` 를 틀로 삼는다.
2. 만든다.
   ```bash
   python3 tools/report/make_report.py 원고.txt -o "documents/<문서 이름>.hwpx" --register --note "한 줄 설명"
   ```
   `--register` 는 `documents/index.json` 의 `items` 에 문서를 올린다(`folders` 는 그대로). 고친 문서는 `<문서 이름> v2.hwpx` 로 새로 만들고 `--ver v2` 를 붙인다. 앞 판은 지우지 않는다.
3. 도구가 내는 `점검:` 줄(개조식 아님, △▽, 날짜 띄어쓰기)을 고친다.
4. 눈으로 확인한다: 저장소를 `python3 -m http.server` 로 띄우고 `hangul.html` 에서 `window.__hwp.openBytes(…)` 로 열어 쪽마다 화면을 찍어 본다(표가 쪽을 넘기는지, 제목만 쪽 끝에 남는지, 자리 상자 크기).
5. CLAUDE.md 작업 규칙대로 커밋 → `main` 병합 → Pages 배포 확인. `documents/` 는 공개 파일이므로 개인정보 · 비공개 내용이 있으면 올리기 전에 묻는다.

### 원고 문법

```
@부서 지휘역량강화센터 지휘역량팀     ← 왼쪽 위 상자 첫 줄
@날짜 2026. 11. 22.(일)              ← 둘째 줄
@부제 부제목                          ← "- 부제목 -" 으로 들어감
@제목 메인제목
@표지 2026. 11.                       ← (긴 보고서만) 표지 쪽. @기관 인천소방학교 와 함께

# 관련근거                            ← Ⅰ. Ⅱ. … 번호는 자동
## 소제목                             ← □ 소제목
○ 본문    - 세부    ↳ 결과    ※ 참고    * 각주    ☑ 점검 항목
**굵게**  __밑줄__  ==형광==  {{파랑}}

[표] 표 제목 | 단위: 명 | 폭: 2 1 1 1    ← 단위 · 폭(칸 비율)은 생략 가능
| 구분 | 전년 | 올해 | 증감 |             ← 첫 줄이 머리 칸
| 교육 인원 | 120 | 135 | ▲ 15 |

[그림] 무엇을 넣을지 | 55             ← 자리 상자. 숫자는 높이(mm). [도표] [사진] 도 같음
[박스] 상자 제목                      ← 강조 상자
☑ 내용
[/박스]
---쪽---                              ← 쪽 나누기
@붙임 1 붙임 제목                     ← 새 쪽에서 붙임 시작
```

## 5. 넘기기 전 점검

- [ ] 여덟 제목이 순서대로 있는가. 빈 절은 `확인 필요` 인가.
- [ ] 모든 줄이 `~함 · ~임`(또는 명사)으로 끝나는가.
- [ ] 숫자가 둘 이상인 곳은 표인가. 증감은 ▲▼ 이고 계산이 맞는가.
- [ ] 자료에 없는 숫자 · 날짜 · 이름을 넣지 않았는가. `확인 필요` 가 몇 곳인지 세어 사용자에게 목록으로 알린다.
- [ ] 본문 · 표 · 붙임 사이 연도 · 부서명 · 금액 · 인원 · 수량이 같은가.
- [ ] 도표 · 그림 자리가 들어갔는가.
- [ ] 결재권자가 물을 것(예산 근거 · 인력 부담 · 안전책임 · 일정)에 본문이 답하는가. 빠졌으면 사용자에게 짚어 준다.

사용자에게는 ① 문서 위치 ② `확인 필요` 목록(채워야 할 자료) ③ 검토 의견(자료 충돌 · 예상 질문)을 나눠서 알린다.

## 6. 한계

- 글꼴은 HY헤드라인M(제목) · 휴먼명조(본문) · 맑은 고딕(표)로 지정한다. 한글이 깔린 PC 에서는 양식과 같게 보이고, 없는 기기는 비슷한 글꼴로 바뀐다.
- 도구는 사진 넣기 · 셀 병합 · 목차 쪽 번호를 하지 않는다. 자리만 잡아 주고, 한글이나 DOCUMENT 에서 채운다.
